Per-request production timeout15s is not whole-body; add independently tested 22s hard wall-clock deadline covering headers+body+normalization. Abort controller plus bounded worker isolation if synchronous normalization hangs; no fire-and-forget pending promises. A request may already be accepted provider-side after abort; do not resend. Proposed **active-run total budget 7200 seconds** across resumed process sessions, measured monotonically and persisted conservatively (a crash cannot reset it). This is a proposed new limit requiring approval, not a change to frozen protocol. Separate approved UTC expiry and daily windows for multi-day quota scheduling; waiting days is not a loophole to infinite run. Active wait/processing counts toward active budget; persist before intervals. Strictest of remaining active budget,22s/request, daily quota and provider wait controls wins.

Minimum10s between dispatch starts, concurrency1; honor stricter RPM/daily restrictions. Default production200/day is shared in-memory and not proof of account quota; never restart to evade it. A category mismatch against target **alone** is not a reason to re-run, tune or delete. On stop, remaining rows explicitly unattempted.

## State transitions and recovery

`UNATTEMPTED → RESERVED → DISPATCH_STARTED → RESPONSE_CAPTURED → RESULT_COMMITTED` or `LOCAL_REJECTED/TERMINAL_ERROR/UNCERTAIN`. Actual request receipt may be unknown; states must not promise delivery. Append durable transitions, atomically commit/fsync result then reconcile marker. Completed success/error with valid hashes never re-sent. Pending marker + no committed result => **UNCERTAIN**: manual evidence reconciliation, no auto replay; preserve slot and input. Guard/local rejection sends0; row remains terminal for this primary invocation or future handling requires documented approval, never implicitly counted as POST. New sessions continue only genuinely unattempted IDs with fresh approved evidence/time window; no duplicate side effects. Ledger disagreement/stale lock requires operator review, not reset/delete. Store old attempts even if new experiment version later permitted.

Store approved sanitized request/response fields in restricted new run folder; cryptographic hash must specify whether over sanitized bytes. Redaction/truncation changes observable evidence and must be flagged. No fallback to production logger for unexpected provider errors. Test every path offline before live; no control described here is claimed to exist yet.
