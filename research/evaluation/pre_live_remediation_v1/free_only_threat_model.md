# FREE_ONLY threat model — read-only findings and proposed remediation

Status: production monetary enforcement **FAIL**; proposed evaluation guard not implemented/tested. No account settings, secrets, provider endpoints or database accessed. References are to inspected `backend/config/kiosApi.js` and `backend/services/classificationService.js`, not README promises.

## Actual paths

- `kiosApi.js:15–19`: empty/unset classification/chat environment falls back to `minimax-m3.1-flash-free`; a nonempty environment override can be any ID, including paid/unknown/whitespace. Explicit `options.model` overrides classification default in payload at 133. The substring check at 114–121 inspects `model || ''`, not the resolved payload model. Its rejection branch is empty regardless of the result; `KIOSAPI_ALLOW_UNVERIFIED_MODELS` does not create real enforcement. Even a literal string `false` for that variable is truthy in the check.
- `KIOSAPI_FREE_ONLY` defaults true; any nonempty value other than case-insensitive `true` disables the branch (no trimming). Neither enabled nor disabled state establishes prices, account group, permitted aliases or a spend cap. Model name containing `free` is not evidence. `KIOSAPI_BASE_URL` can change endpoint independently of model/cost assumptions (12–13).
- Known alias may be repriced/rerouted without changing ID. `data.model || model` at 190 masks absent provider identity with requested alias; returned ID is not proof of weight version or price. No route/snapshot attestation exists locally. Do not infer vendor identity or zero debit from alias.
- Missing key stops before fetch (105–109), daily limit stops at 58–68; neither is a financial protection. Counter defaults200, shared with chatbot, process-local, reset UTC/restart, and counts before POST. No billing/retry/redirect safeguards exist at this layer; default fetch redirects are not explicitly disabled.
- No automatic cross-model paid fallback was found in the inspected adapter/service. Failure yields **local manual-review output**, not another provider call (`classificationService:261–292`). Nonetheless external router behavior and caller/environment fallback remain unverified. Chat calls share the adapter and can consume quota outside the isolated study.
- Sanitization uses key as unescaped regex (`197–198`); metacharacters can cause incomplete redaction or regex errors. Provider messages may contain other secrets. Service logs `error.message` and returns it in `error`; do not treat production logger as safe for arbitrary provider errors.

## Proposed fail-closed guard (evaluation-only, not a code change)

Resolve effective base URL/model/config exactly once before loading service; require explicit manifest values, reject empty model/default ambiguity and unknown env flags. Compare outbound payload with that frozen manifest at transport boundary immediately before sending; reject mismatch without incrementing actual POST count. Require exact allowlisted model/endpoint/group identity and **current verifiable account-specific evidence** for zero effective prices and every fee, plus an enforceable provider no-paid-debit restriction. Expired/missing/inconsistent evidence => deny. Exact allowlist is necessary but insufficient to guarantee cost.

No substring matching, silent alternate model, "allow unverified" escape, router auto-selection, unknown redirects, or inherited chat traffic. Aliases permitted only with recorded resolution/limitations and provider evidence; unresolved/dynamic resolution => deny. Check provider-side spend lock before send; observing a charge afterward cannot retroactively guarantee Rp0. Missing returned ID => provenance unavailable and stop, never promote alias to provider-returned. Zero usage.cost is not equivalent to zero account charge; repeated pricing checks cannot eliminate time-of-check/time-of-use repricing without provider enforcement.

Offline tests must use injected synthetic evidence and fake transport; they prove software policy, not account eligibility/billing. Any future production patch needs separate authorization/review. Closing B03 requires proven evaluation guard + offline tests AND verified provider monetary restriction (B02); production adapter itself remains FAIL until separately repaired.
